## Ideas (not implemented)

Candidate bands from `prompts/resources/era5_gee.txt` (ECMWF/ERA5/HOURLY):
- `wind_gust_since_previous_post_processing_10m` (m/s): max 3 s gust (WMO) within each hour; convection included only from 2008-10-01 (check series across that date). Daily `max` = wind-risk counterpart of `PPT` `max` (peak rate). Possible code: `WDG`.
- `maximum_2m_temperature_since_previous_post_processing` / `minimum_2m_temperature_since_previous_post_processing` (K): extremes between the hourly samples, so true daily Tmax/Tmin; current `TAS` max/min use only the 24 hourly values and slightly underestimate extremes.
- `u_component_of_wind_100m` / `v_component_of_wind_100m`: 100 m wind (e.g. wind energy), same speed/direction method as 10 m.
- `surface_runoff` / `sub_surface_runoff` (m): split of `Q`; considered and declined (surface scheme too simplified, `Q` `max` is enough for flood-risk screening).
- Speed-weighted (resultant) wind direction `atan2(-mean u, -mean v)`: differs from `WDA` (all hours weighted equally) on days when the wind turns. WDU/WDV are purged, so it would need u/v means back (or a `dir_vector_mean` stat).
- `MONTHLY/` and `ANNUAL/` folders next to `DAILY/` in each `{VAR}/`.
